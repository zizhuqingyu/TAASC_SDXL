# A6000 单卡版：改动与原因

## 运行

```bash
python inference_sdxl.py --model /home/zjs/dataset/weight
```

沿用原 JSONL 数据路径、30 步、CFG 7.0、1024×1024、单张输出和
`internvl_client.client_para(image_path, annotation)` 接口。
如你已经修改过评分服务协议，请继续使用你自己的 `internvl_client.py`。
本包没有环境安装脚本，没有运行 GPU 实测。

## 一、两轮后 OOM 是否是重复加载？

对你提供的压缩包逐项检查：主程序在样本循环外执行一次 `load_pipeline()`；
每轮没有再次调用 `from_pretrained()` / `from_single_file()`。
因此，**现有代码不能支持“每轮重新加载一套 SDXL”的判断**。
默认 CPU offload 会搬移同一模型对象，这和重复从硬盘读取权重是两回事。

旧版第一轮没有反馈目标，走原生 attention processor；从第二轮才启用
显式 cross-attention 计算，其显存路径发生变化。旧版虽已有分块，但仍临时
保留多个 GPU chunk 输出；嵌入缓存留在 GPU，卸载依赖通用 offload hooks。
这些是可降低的占用，并不等于已发现了能解释 48GB 耗尽的确定泄漏。

你确认 InternVL 也运行在同一张 A6000 上。其空闲时占用不能代表评分时的峰值；
我们目前没有完整报错堆栈、各阶段显存或你的服务端代码，无法认定 OOM 究竟
发生在 SDXL 去噪、VAE 解码、评分请求还是其他进程中。

### 本版的显存修改

| 位置 | 改动 |
|---|---|
| 权重加载 | 仍只加载一次，启动时打印 pipeline / U-Net 对象标识 |
| 模型驻留 | 默认使用显式阶段调度，不再安装 Accelerate CPU offload hooks |
| 编码 | 只有两套文本编码器进入 GPU，结束后移回 CPU；短语按 1 条编码 |
| 缓存 | 整句/短语 embedding、累计注意力图均保存在 CPU |
| 去噪 | 只有 U-Net 进入 GPU；仍由官方 pipeline 和原 scheduler 执行 |
| 解码 | 去噪返回 latent 后先卸载 U-Net，再加载 VAE；保留原生 latent 缩放和精度处理 |
| attention | query 分块默认 256；预分配输出，取消 GPU chunk 列表及最终拼接副本 |
| 轮次结束 | 清空控制器张量引用，将 SDXL 模块移回 CPU，再释放未使用的 CUDA 缓存 |
| InternVL | 发请求前 SDXL 模块已回到 CPU；不对外部服务进程强制卸载或重启 |
| 日志 | 编码、去噪、解码、评分前后打印显存，并记录到样本 JSON |

这是用 CPU 内存和搬移时间换取更低 GPU 峰值。CPU 内存仍需容纳完整 SDXL 权重。
若明确不需要卸载，可用 `--no-cpu_offload`，但同卡评分时建议保留默认值。
`empty_cache()` 只释放当前进程未使用的缓存；不能释放仍有引用的 GPU 张量，
更不能清除另一个 InternVL 进程持有的权重或缓存。

日志字段：`allocated_gib` 是当前进程的 PyTorch 张量占用；
`reserved_gib` 是当前进程的 PyTorch allocator 保留量；
`device_free_gib` 是整张卡当前空闲容量。三者不是同一个数。
出现 OOM 会记录阶段并停止，不反复重新加载模型或盲目重试生成。

## 二、为什么效果可能比原生 SDXL 差？

没有看到具体图片与评分，不能确定你遇到的是语义错误、画质退化还是数值异常。
代码中有以下明确风险：

1. **旧默认干预偏强。** 第一轮所有短语的 lambda=0.5，意味着受控 token 的
   表示有一半来自独立短语编码。后续最多升到 0.9。单独编码的短语缺少整句
   上下文，这可能削弱颜色绑定、对象间关系等信息。这组参数沿用了 SD1.4，
   未经 SDXL 调优；之前应更清楚地说明这一点。
2. **空间稳定不等于空间正确。** 已经聚集在错误对象上的注意力也可能稳定，
   对其增强可能进一步固化错误。方法中的稳定性指标不能证明关系已经正确。
3. **视觉评分会有误差。** 若正确属性被持续低估，反馈仍会增强它。
   评分通过也不能保证画面美观。
4. **旧版保留最后一轮。** 这符合论文原停止策略，但不保证最后一轮最好。
5. **短语重复和重叠。** 原实现对重叠 token 按顺序覆盖；同一个词出现在
   多个对象上时仍是短语级控制，不能自动变成按对象实例区分的局部控制。

### 本版的保守参数与结果选择

| 参数 | 旧版 | 新默认 |
|---|---:|---:|
| lambda 初始值 | 0.5 | 0.0 |
| lambda 更新系数 eta | 0.25 | 0.1 |
| 单轮最大增量 | 0.05 | 0.02 |
| lambda 上限 | 0.9 | 0.25 |
| attention 最大 gain | 0.5 | 0.15 |
| 重叠短语 | 后者覆盖 | 平均非零补偿位移 |
| 最终选择 | 最后一轮 | 最小短语评分最高者；平分时比较平均分 |

第一轮不执行语义补偿或反馈注意力注入，并保存在 `baseline/<id>.png`。
最终图片保存为 `<id>.png`。各轮默认保持相同 seed，便于比较。
当你显式设置非零初始 lambda 时，首轮放入 `initial/`，不会冒称原生 baseline。
如果所有后续轮次的选择评分都未超过初次生成，会保留初次生成的图片。

**以上是降低干预风险的工程默认值，不是已验证最优的 SDXL 参数，
也不保证审美质量提升。** “最好”仅指指定的 VLM 评分排序。
尤其是“选最好一轮”和“重叠位移平均”是原论文之外的工程策略，
做论文实验时必须明确报告，不能把它们当成完全相同的原配置。

如需原控制强度及原返回策略，同时保留显存修复：

```bash
python inference_sdxl.py \
  --lambda_init 0.5 --lambda_eta 0.25 --lambda_max_step 0.05 --lambda_max 0.9 \
  --attention_max_gain 0.5 --overlap_mode last --return_strategy last
```

如仅需要原生 SDXL 条件生成：

```bash
python inference_sdxl.py --disable_agent --lambda_init 0 --outdir ./native_sdxl
```

## 三、这些代码究竟怎样修改了 SDXL？

### 1. 文本条件

SDXL 两套文本编码器按官方 `encode_prompt` 路径编码整句和独立短语。
在对应 token 位置执行：

`C_new = (1 - lambda) * C_prompt + lambda * E_phrase`

跳过短语开头的 BOS；保留整句的 pooled embedding 和负向条件。
改变的是送入 U-Net 的条件张量，没有改编码器的模型权重。

### 2. U-Net 的交叉注意力

替换 `attn2` 的 processor，以取得 softmax 后但尚未增强的原始注意力。
将目标短语的 token 响应求和、head 平均，统一到 16×16 并跨层平均。
使用 SD1.4 的余弦相似度、IoU、质心位移组合分数判断连续 3 次转换是否稳定。
稳定后，在上一完成步的高响应区域中，对低分短语的 logits 注入：

`logits_new[q,j] = logits[q,j] + log(1 + gain)`

仅对条件分支、目标 token 和掩膜内位置注入；自注意力不替换。
softmax 的分母会改变，因此掩膜内其他 token 的概率也会随之变化。
这种控制并没有加入“物体必须位于左侧”之类的显式几何约束。

### 3. 图片之间的反馈循环

生成一张完整图片 → InternVL 按标注评分 → 更新低分短语的 lambda 与 gain →
从相同初始随机噪声重新生成下一轮。这不是对上张图片进行 img2img 编辑。

U-Net/CLIP/VAE 权重均冻结，原 scheduler、CFG 和去噪流程保留；
没有训练、反向传播、LoRA、Refiner 或模型权重合并。
本版新增的显存调度只改变模块在 CPU/GPU 上驻留的阶段。
